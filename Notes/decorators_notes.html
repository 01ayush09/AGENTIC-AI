01 · Foundation

What is a Decorator?

A decorator is a higher-order function that wraps another function or class, transparently adding behaviour before, after, or around it — without modifying its source code. In Python, decorators leverage the fact that functions are first-class objects.

Core Idea

A decorator takes a callable, wraps it inside another callable, and returns the wrapper. The original callable's name still points to the new, enhanced version.

Conceptually: decorated_fn = decorator(original_fn). The @ syntax is pure syntactic sugar for that assignment.

General Decorator Anatomy
def my_decorator(func):
    from functools import wraps
    @wraps(func)                     # preserve original metadata
    def wrapper(*args, **kwargs):
        # --- code BEFORE the function ---
        result = func(*args, **kwargs)  # call the original
        # --- code AFTER the function ----
        return result
    return wrapper

@my_decorator
def greet(name: str) -> str:
    return f"Hello, {name}"

Decorator with Arguments (Factory Pattern)

def repeat(times: int):          # outer factory
    def decorator(func):           # middle: real decorator
        @wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(times=3)
def ping(): print("ping")

02 · Applicability

When Must You Use a Decorator?

Use a decorator whenever you need to apply the same cross-cutting behaviour to multiple functions/classes without copy-pasting code. Classic production triggers:

CASE 01
Cross-cutting concerns Logging, metrics, tracing — same wrapper on every endpoint or service method.
CASE 02
Retry & resilience Automatic retry with back-off on flaky LLM API calls or DB connections.
CASE 03
Caching / memoisation Expensive embedding or tokenisation calls that return the same result for the same input.
CASE 04
Access control / auth Protect API routes; enforce role-based guards before handler logic runs.
CASE 05
Interface contracts Force subclasses to implement methods (@abstractmethod).
CASE 06
Gradient management Disable gradient tracking during inference to save GPU memory.
CASE 07
Data validation Pydantic field/model validators run automatically on model instantiation.
CASE 08
Resource management Context managers as decorators for setup/teardown (DB sessions, file handles).
Rule of Thumb

If you find yourself writing the same boilerplate in three or more functions, extract it into a decorator. One definition, infinite applications.

03 · Syntax Reference

Decorator Syntax Patterns

Pattern 1 — Simple decorator
@decorator
def function(): ...
Pattern 2 — Decorator with arguments
@decorator(arg1, arg2)
def function(): ...
Pattern 3 — Stacked decorators (applied bottom-up)
@decorator_a
@decorator_b
@decorator_c
def function(): ...
# equivalent to: decorator_a(decorator_b(decorator_c(function)))
Pattern 4 — Class decorator
@dataclass
class Config:
    lr: float = 1e-4
    epochs: int = 10
Pattern 5 — Async decorator
import asyncio
from functools import wraps

def async_log(func):
    @wraps(func)
    async def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return await func(*args, **kwargs)
    return wrapper

@async_log
async def fetch_embeddings(text): ...

01 @property RAG · LLM · ML

Lazy-loads the embedding model only on first access, caching it as a private attribute. Common in RAG retrievers.

class EmbeddingRetriever:
    def __init__(self, model_name: str):
        self.model_name = model_name
        self._model = None          # not loaded yet

    @property
    def model(self):
        # loaded once, reused forever
        if self._model is None:
            self._model = SentenceTransformer(self.model_name)
        return self._model

    def embed(self, text: str):
        return self.model.encode(text)  # triggers load on first call

02 @staticmethod RAG · LLM · ML

Pure utility method on a chunking class — no instance state needed, but logically belongs with the chunker.

class DocumentChunker:
    def __init__(self, chunk_size=512, overlap=64):
        self.chunk_size = chunk_size
        self.overlap = overlap

    @staticmethod
    def clean_text(text: str) -> str:
        # strip whitespace, normalise unicode — no self needed
        import unicodedata
        text = unicodedata.normalize("NFKC", text)
        return " ".join(text.split())

    def chunk(self, text: str) -> list[str]:
        text = DocumentChunker.clean_text(text)  # call without self
        return [text[i:i+self.chunk_size]
                for i in range(0, len(text), self.chunk_size - self.overlap)]

03 @abstractmethod RAG · LLM · ML

Defines a retriever interface — forces every backend (Dense, BM25, Hybrid) to implement retrieve().

from abc import ABC, abstractmethod

class BaseRetriever(ABC):
    @abstractmethod
    def retrieve(self, query: str, top_k: int) -> list[dict]:
        """Return top_k relevant documents for query."""

    @abstractmethod
    def index(self, documents: list[str]) -> None:
        """Index a list of documents."""

class DenseRetriever(BaseRetriever):
    def retrieve(self, query, top_k):
        return self.vector_store.similarity_search(query, k=top_k)

    def index(self, documents):
        self.vector_store.add_documents(documents)

# BaseRetriever()  ← would raise TypeError at runtime

05 @torch.no_grad() LLM · ML

Wraps the inference function so PyTorch never builds a computation graph — critical for production serving latency and GPU memory.

import torch

@torch.no_grad()
def generate_embeddings(model, texts: list[str], device="cuda"):
    from transformers import AutoTokenizer
    tokenizer = AutoTokenizer.from_pretrained(model.config._name_or_path)
    inputs = tokenizer(texts, return_tensors="pt",
                       padding=True, truncation=True).to(device)
    outputs = model(**inputs)                # no grad graph built
    embeddings = outputs.last_hidden_state[:, 0, :]  # [CLS] token
    return embeddings.cpu().numpy()

# torch.cuda.memory_allocated() is ~40% lower vs without @no_grad

06 @lru_cache RAG · LLM · ML

Caches tokenisation results — identical prompts hitting the cache avoid redundant tokeniser calls under concurrent load.

from functools import lru_cache
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("gpt-4")  # loaded once

@lru_cache(maxsize=1024)
def count_tokens(text: str) -> int:
    # cache keyed by text string; pure function — same input → same output
    return len(tokenizer.encode(text))

# First call: tokenises
count_tokens("What is retrieval-augmented generation?")  # → 6
# Second call: cache hit, zero compute
count_tokens("What is retrieval-augmented generation?")  # → 6 instantly

07 @field_validator RAG · LLM

Validates incoming LLM generation parameters at the API boundary — rejects bad values before they reach the model.

from pydantic import BaseModel, field_validator

class GenerationRequest(BaseModel):
    prompt:      str
    temperature: float = 0.7
    max_tokens:  int   = 512
    top_k:       int   = 50

    @field_validator("temperature")
    @classmethod
    def check_temperature(cls, v: float) -> float:
        if not (0.0 <= v <= 2.0):
            raise ValueError(f"temperature must be 0–2, got {v}")
        return v

    @field_validator("max_tokens")
    @classmethod
    def check_tokens(cls, v: int) -> int:
        if v > 4096:
            raise ValueError("max_tokens cannot exceed 4096")
        return v

req = GenerationRequest(prompt="Explain RAG", temperature=2.5)
# ValidationError: temperature must be 0–2, got 2.5

08 @retry RAG · LLM

Wraps an OpenAI API call with exponential back-off — transparently handles rate-limit and timeout errors in production.

from tenacity import (
    retry, stop_after_attempt,
    wait_exponential, retry_if_exception_type
)
import openai

@retry(
    wait=wait_exponential(multiplier=1, min=2, max=60),
    stop=stop_after_attempt(5),
    retry=retry_if_exception_type((
        openai.RateLimitError,
        openai.APITimeoutError,
    )),
    reraise=True,
)
async def call_llm(messages: list[dict]) -> str:
    response = await openai.chat.completions.create(
        model="gpt-4o",
        messages=messages,
    )
    return response.choices[0].message.content
# On RateLimitError: waits 2s, 4s, 8s … up to 60s, max 5 tries
python
09 @contextmanager RAG · ML

Manages a SQLAlchemy database session for the vector-store metadata layer — always commits or rolls back, never leaks connections.

from contextlib import contextmanager
from sqlalchemy.orm import sessionmaker

Session = sessionmaker(bind=engine)

@contextmanager
def get_db_session():
    session = Session()
    try:
        yield session          # caller uses this session
        session.commit()
    except Exception:
        session.rollback()
        raise
    finally:
        session.close()

# Usage in RAG metadata store:
with get_db_session() as db:
    db.add(DocumentRecord(content=chunk, embedding_id=eid))
# session automatically committed & closed
