01 · Foundation

What is a Generator?

A generator is a special kind of iterator in Python that produces values lazily — one at a time, on demand — instead of computing and storing everything in memory at once. A generator function uses the yield keyword instead of return; each call to next() resumes execution from where it last paused.

Core Idea

A generator suspends its own execution at every yield, hands a value to the caller, and remembers its entire local state (variables, instruction pointer) until the next call. This makes infinite sequences and massive data pipelines possible with O(1) memory.

There are three forms: generator functions (use yield), generator expressions (inline comprehension-style), and async generators (use async def + yield).

Generator Function — Anatomy
def my_generator(n: int):
    # setup code runs once
    for i in range(n):
        # pauses here, yields value to caller
        yield i * i          # resumes on next()
    # teardown runs after last yield

gen = my_generator(5)    # returns generator object — no work done yet
next(gen)               # → 0  (runs until first yield)
next(gen)               # → 1  (resumes from yield)
for v in my_generator(5): print(v)  # 0 1 4 9 16

Generator vs Regular Function

# Regular function — loads ALL items into memory
def get_all_chunks(docs): return [chunk for doc in docs for chunk in doc]

# Generator — yields one chunk at a time, O(1) memory
def stream_chunks(docs):
    for doc in docs:
        for chunk in doc:
            yield chunk
python

Generator Expression

# List comprehension — materialises entire list
squares_list = [x**2 for x in range(1_000_000)]   # ~8 MB RAM

# Generator expression — lazy, parentheses instead of brackets
squares_gen  = (x**2 for x in range(1_000_000))   # ~128 bytes

02 · Applicability

When Must You Use a Generator?

Use a generator whenever data is too large to fit in memory, arrives incrementally, or needs to be processed in a pipeline. Classic production triggers:

CASE 01
Streaming LLM tokens Yield tokens one-by-one from the model API for real-time streaming responses.
CASE 02
Large dataset batching Stream millions of training samples in mini-batches without loading the full dataset.
CASE 03
Document chunking pipelines Lazily chunk, clean, and embed large corpora in RAG ingestion pipelines.
CASE 04
Infinite sequences Produce an unbounded sequence (IDs, steps, epochs) that the caller controls when to stop.
CASE 05
Async data streams Async generators for concurrent I/O — reading from queues, sockets, or async APIs.
CASE 06
Chaining transforms Compose multiple lazy transformations into a zero-copy pipeline using itertools.
CASE 07
Memory-constrained inference Stream inference results over large validation sets without OOM on GPU nodes.
CASE 08
Data augmentation on-the-fly Apply random augmentations lazily during training instead of pre-generating all variants.
Rule of Thumb

If the full result set would be larger than available RAM, or if the caller doesn't always need every item, use a generator. It is always cheaper to not produce a value than to produce and discard it.

03 · Syntax Reference

Generator Syntax Patterns

Pattern 1 — Generator function (yield)
def gen_function(items):
    for item in items:
        yield transform(item)
Pattern 2 — Generator expression
gen = (transform(x) for x in items if condition(x))
Pattern 3 — yield from (delegation)
def flat_gen(nested):
    for sub in nested:
        yield from sub      # delegates to inner iterable
Pattern 4 — Async generator
async def async_gen(source):
    async for item in source:
        yield item

# consumption:
async for val in async_gen(source): ...
Pattern 5 — send() bidirectional generator
def accumulator():
    total = 0
    while True:
        value = yield total   # yield sends total out, receives value in
        total += value

acc = accumulator()
next(acc)       # prime the generator → 0
acc.send(10)    # → 10
acc.send(5)     # → 15

01 yield-based streaming generator RAG · LLM · ML

Lazily chunks a corpus of documents for a RAG ingestion pipeline — processes one document at a time, never loads all chunks into memory.

from typing import Iterator

def chunk_corpus(
    file_paths: list[str],
    chunk_size: int = 512,
    overlap: int = 64,
) -> Iterator[dict]:
    for path in file_paths:
        with open(path) as f:
            text = f.read()
        start = 0
        while start < len(text):
            chunk = text[start : start + chunk_size]
            yield {"source": path, "text": chunk, "start": start}
            start += chunk_size - overlap   # sliding window

# Pipeline: stream chunks → embed → upsert — zero intermediate lists
for chunk in chunk_corpus(all_pdfs, chunk_size=512):
    vector_store.upsert(embedder.embed(chunk["text"]), chunk)

02 async for generators LLM

Streams tokens from OpenAI's async API and yields them to a FastAPI streaming response — enables real-time character-by-character output.

import openai
from fastapi.responses import StreamingResponse

async def stream_llm_tokens(prompt: str):
    """Async generator: yields each token chunk as it arrives."""
    client = openai.AsyncOpenAI()
    stream = await client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        stream=True,
    )
    async for chunk in stream:
        delta = chunk.choices[0].delta.content
        if delta:
            yield delta           # push token to caller immediately

# FastAPI endpoint wrapping the async generator
async def chat_stream(prompt: str):
    return StreamingResponse(
        stream_llm_tokens(prompt),
        media_type="text/event-stream",
    )

03 itertools.chain() RAG · ML

Merges multiple retriever result lists into one flat lazy stream for re-ranking — no intermediate concatenated list needed.

from itertools import chain

def hybrid_retrieve(
    query: str,
    dense_retriever,
    sparse_retriever,
    top_k: int = 20,
) -> list[dict]:
    dense_results  = dense_retriever.retrieve(query, top_k)   # list
    sparse_results = sparse_retriever.retrieve(query, top_k)  # list
    web_results    = web_retriever.retrieve(query, top_k // 2)

    # chain merges all three lazily — one iterator, no copy
    all_docs = chain(dense_results, sparse_results, web_results)

    seen, unique = set(), []
    for doc in all_docs:
        if doc["id"] not in seen:
            seen.add(doc["id"])
            unique.append(doc)
    return reranker.rerank(query, unique)[:top_k]

04 itertools.islice() RAG · ML

Takes the first N chunks from an infinite or very large corpus generator without loading the rest — essential for debugging pipelines.

from itertools import islice

def evaluate_pipeline(corpus_gen, retriever, n_samples=200):
    """Run evaluation on first n_samples only — corpus_gen may be infinite."""
    hits = 0
    # islice never materialises the full corpus — just takes 200 items
    for sample in islice(corpus_gen, n_samples):
        docs = retriever.retrieve(sample["query"], top_k=5)
        if sample["answer_id"] in {d["id"] for d in docs}:
            hits += 1
    return hits / n_samples   # recall@5

# Usage: evaluate on first 200 from a 10M-sample corpus generator
recall = evaluate_pipeline(stream_corpus("data/"), retriever, 200)

05 batched() / chunked() generators RAG · LLM · ML

Groups a flat stream of texts into batches for efficient embedding API calls — avoids per-item round-trips to the embedding service.

from itertools import batched   # Python 3.12+
# or: from more_itertools import chunked  (older Python)

def batch_embed(texts: list[str], model, batch_size: int = 64):
    """Embed all texts in batches, yield (text, embedding) pairs."""
    for batch in batched(texts, batch_size):
        # one API call per batch instead of per text
        embeddings = model.encode(list(batch), batch_size=batch_size)
        yield from zip(batch, embeddings)

# Index 1M chunks with 64-text batches → only 15,625 API calls
for text, emb in batch_embed(all_chunks, embedding_model):
    vector_store.add(emb, metadata={"text": text})

06 DataLoader generator pipeline ML

Custom PyTorch Dataset wired into a DataLoader — the training loop pulls one GPU-ready batch at a time with background prefetching.

import torch
from torch.utils.data import Dataset, DataLoader

class TextDataset(Dataset):
    def __init__(self, file_path, tokenizer, max_len=512):
        self.samples = open(file_path).readlines()  # lines only
        self.tokenizer = tokenizer
        self.max_len = max_len

    def __len__(self): return len(self.samples)

    def __getitem__(self, idx):
        return self.tokenizer(
            self.samples[idx].strip(),
            truncation=True, max_length=self.max_len,
            return_tensors="pt",
        )

loader = DataLoader(
    TextDataset("train.txt", tokenizer),
    batch_size=32, shuffle=True, num_workers=4, pin_memory=True,
)

# Training loop — DataLoader acts as a generator
for epoch in range(3):
    for batch in loader:          # pulls next batch lazily
        loss = model(**batch).loss
        loss.backward()
        optimizer.step()

09 zip() / enumerate() RAG · LLM · ML

Pairs queries with retrieved documents and tracks indices for logging — both built-ins produce lazily, zero extra memory.

def evaluate_rag(queries, ground_truths, retriever, top_k=5):
    """Compute Hit Rate and MRR over a query set."""
    hits, reciprocal_ranks = [], []

    # enumerate gives (index, query) lazily
    # zip pairs query with its ground truth lazily
    for i, (query, truth) in enumerate(zip(queries, ground_truths)):
        docs = retriever.retrieve(query, top_k=top_k)
        ids  = [d["id"] for d in docs]

        hit = truth in ids
        hits.append(int(hit))
        rank = ids.index(truth) + 1 if hit else 0
        reciprocal_ranks.append(1 / rank if rank else 0)

        if i % 100 == 0:
            print(f"[{i}] HR={sum(hits)/len(hits):.3f}")

    return {"hit_rate": sum(hits)/len(hits),
            "mrr":      sum(reciprocal_ranks)/len(reciprocal_ranks)}

10 async_generator LLM

Full async generator pipeline for a Server-Sent Events (SSE) endpoint — streams LLM tokens to the browser with back-pressure support.

import asyncio
from fastapi import APIRouter
from fastapi.responses import StreamingResponse
from sse_starlette.sse import EventSourceResponse

router = APIRouter()

async def token_event_generator(prompt: str):
    """Async generator that emits SSE-formatted token events."""
    async for token in stream_llm_tokens(prompt):   # from example 02
        yield {
            "event": "token",
            "data": token,
        }
        await asyncio.sleep(0)   # yield control to event loop

    yield {"event": "done", "data": "[END]"}   # sentinel event

@router.post("/stream")
async def stream_endpoint(prompt: str):
    # EventSourceResponse consumes the async generator
    return EventSourceResponse(token_event_generator(prompt))

# Client receives: event: token\ndata: Hello\n\nevent: token\ndata: world\n\n...
